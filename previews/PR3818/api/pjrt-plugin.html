PJRT Plugin API ​

Reactant.XLA.PJRT.Plugin implements the PJRT C API in Julia, so that a PJRT plugin can be written by implementing the Julia interfaces below instead of the C API. Reactant.Accelerators.JuliaCPU is the reference implementation. See the Julia as backend tutorial for an overview of how they fit together.

Warning

This API is experimental and may change without deprecation.

Reactant.XLA.PJRT.Plugin.make_api Method
julia
make_api(plugin::AbstractPlugin; extensions=()) -> PluginApi

Build the PJRT_Api function table of plugin.

extensions is a collection of Extension types, which are built as E(plugin, next) and advertised to XLA through the extension chain of the table, in the given order, e.g.

julia
make_api(MyPlugin(); extensions=[MemoryDescriptionsExtension, FFIExtension])

Each extension type can be given only once.

Store the result in a global (e.g. a const Ref) set from the plugin's __init__, and pass unsafe_convert(Ptr{CAPI.PJRT_Api}, api) to XLA.

source
Reactant.XLA.PJRT.Plugin.AbstractPlugin Type
julia
AbstractPlugin

A type representing a PJRT plugin. Used for dispatching on plugin entrypoints, like client creation or the topologies created without a client.

Pass an instance to make_api to build its PJRT_Api.

It must be stateless: its type P must be Base.issingletontype(P) with an empty constructor P(). Plugin-wide state (e.g. a registry of FFI handlers) belongs in globals of the module of the plugin.

julia
AsyncTrackingEvent(description::String)

A scoped event that tells a device that there is asynchronous work depending on its activity, from its creation by async_tracking_event until C destroys it.

description is the one given by C (e.g. for tracing), and done is an Event that is set once the work is done, i.e. when PJRT_AsyncTrackingEvent_Destroy is called. A plugin that supports tracking events can keep them, and wait for (or check with isready) their done event.

Backs PJRT_AsyncTrackingEvent opaque type.

source
Reactant.XLA.PJRT.Plugin.Event Type
julia
Event()

A PJRT_Event: a one-shot, thread-safe completion signal, which may carry an Error if the operation failed.

It starts unset and is set exactly once with notify. Use wait to block until it is set and isready to check without blocking. Callbacks registered with PJRT_Event_OnReady run when it is set, or immediately if it already is.

Every PJRT_Error it hands to C (from PJRT_Event_Error, PJRT_Event_Await or an on-ready callback) is a new copy of event.error, since each receiver destroys its own.

Warning

It is GC rooted when handed to C and unrooted by PJRT_Event_Destroy.

Base.notify Function
julia
notify(event::Event, err::Union{Nothing,Error}=nothing)

Set event, as failed with err or as successful if err is nothing. This wakes every task blocked in wait and then runs the on-ready callbacks, each with its own copy of err.

Callbacks run outside the lock, in the calling task, so they may call back into event.

Throws invalid_argument if event is already set.

Reactant.XLA.PJRT.Plugin.buffer_from_host_buffer Method
julia
buffer_from_host_buffer(
    client::Client, dev::Device, mem::Memory, data::Ptr, type, dims, host_layout, device_layout,
    host_buffer_semantics,
) -> Buffer

Return a new buffer placed on memory mem of device dev, with a copy of the host data. The new buffer has element type type::CAPI.PJRT_Buffer_Type and dimensions dims::Vector{Int64}.

Arguments

  • mem is always one of addressable_memories(dev). PJRT may pass only one of the two, so the caller fills in the other:

    • only dev given: mem is default_memory(dev).

    • only mem given: dev is one of addressable_devices(mem).

  • host_layout::Union{Nothing,StridedMemoryLayout} is the layout of data: nothing for dense data in major-to-minor order, or the byte strides of each dimension (which can be negative, if data points inside the array).

  • device_layout::Union{Nothing,MemoryLayout} is nothing for the default layout.

  • host_buffer_semantics::CAPI.PJRT_HostBufferSemantics says how long data stays valid.

  • done_with_host_buffer is signaled as soon as this returns, so data must not be accessed afterwards.

The caller GC-roots the returned buffer.

Backs PJRT_Client_BufferFromHostBuffer.

Reactant.XLA.PJRT.Plugin.compile Method
julia
compile(client::Client, code::MLIR.IR.Module, options::Vector{UInt8})

Compile code for the devices of client and return a loaded executable.

Arguments

  • code: MLIR module. Reactant always sends this format: a StableHLO portable artifact (VHLO bytecode) serialized to the version in the plugin's stablehlo_current_version attribute, or to XLA's default version if the plugin doesn't set it.

  • options is a serialized CompileOptionsProto (replica/partition counts, device assignment, ...).

Warning

code and options are owned by C and only valid during the call, so they must be copied before being stored.

The caller GC-roots the returned executable.

julia
create_alias_buffer(client::Client, mem::Memory, type, dims, layout) -> Tuple{Buffer,Any}

Return (alias, fulfill): a new buffer alias placed on memory mem, with element type type::CAPI.PJRT_Buffer_Type and dimensions dims::Vector{Int64}, which aliases a buffer that is not known yet; and a callable fulfill.

alias is not ready until fulfill(result) is called, where result is either the aliased Buffer or an Error that alias must fail with. fulfill is called at most once, by PJRT_Client_FulfillAliasBuffer, and its errors are returned to C.

layout::Union{Nothing,MemoryLayout} is nothing for the default layout.

The caller GC-roots alias, and keeps fulfill alive until it is called.

Backs PJRT_Client_CreateAliasBuffer.

Reactant.Accelerators.JuliaCPU.handle Function
julia
handle(::Val{opname}, operands::Tuple, attributes::NamedTuple, results::Tuple)

Run the MLIR op opname (e.g. Symbol("stablehlo.add")) and return its results.

  • operands: Julia arrays, i.e. row-major MLIR tensors seen as column-major arrays with reversed dimensions, or Tokens.

  • attributes: the op attributes, decoded by decode_attribute.

  • results: the type of each result, as (; eltype, size) with size in Julia order (i.e. reversed), or Token for tokens.

Like MLIR values, the return value depends on the number of results: it is ignored if there are none, it is the result itself if there is one (%N), and it must be a tuple with one entry per result if there are several (%N:2, bound to %N#0 and %N#1).
